# raw_mave_data

Hand-populated starting point for the Dockerized variant-annotation pipeline
(`scripts/variant_annotation_pipeline.sh`, driven by
`scripts/run_variant_annotation_pipeline.sh` -- see
`docs/variant_annotation_pipeline.md`). This is the one directory in the
pipeline's data flow that isn't auto-generated — everything downstream is
produced by running the pipeline.

## Data flow

```
data/raw_mave_data/                       (this directory -- you populate it)
        |  scripts/run_variant_annotation_pipeline.sh copies it in
        v
data/intermediate/variant_annotation/data/ (gitignored; mounted as the
                                             variant-annotation pipeline's
                                             VARIANT_DATA_DIR for the run)
        |  variant_annotation_pipeline.sh runs Steps 1-19 + condensed/expanded
        |  frame assembly
        v
data/mave_data/                            (final gzipped outputs, tracked)
```

## Expected contents

Files sit directly in this directory (no `cvfg/` or version subdirectories).
Only the files `scripts/variant_annotation_pipeline.sh` actually reads as
*input* need to be here — the `cvfg_variants.1.tsv` .. `.19.tsv` intermediates
and the final `integrated_variant_effect_dataset*.tsv` files are generated by
the run itself and should not be pre-populated.

This directory is currently empty of pipeline inputs -- Step 1's input,
`cvfg_variants.0.tsv`, lives at `data/input/maves/cvfg_variants.0.tsv`
instead, alongside `score_sets.tsv`/`Supplementary_Data_3.xlsx` below.
`scripts/run_variant_annotation_pipeline.sh` copies it into the staged
directory whenever Step 1 is about to run (a full run, or `--step 1`) -- see
`docs/variant_annotation_pipeline.md`.

`MANE.GRCh38.v1.5.summary.txt.gz` (RefSeq/Ensembl accession mapping, read by
Step 2), `score_sets.tsv` (dataset name / score-set mapping, read by Steps 11
and 15), `Supplementary_Data_3.xlsx` (assay metadata, read by Step 16), and
`extended_ensembl_consequence.csv.gz` (VEP-term mapping, read by Step 17)
are **not** expected here -- they live in `data/input/reference/`,
`data/input/maves/`, and `data/input/consequence/` instead, alongside
`data/input/predictors/` (see `docs/build_training_variant_files.md` and
`docs/annotate_simplified_consequence.md`). `MANE.GRCh38.v1.5.summary.txt.gz`,
`score_sets.tsv`, and `Supplementary_Data_3.xlsx` are copied by
`scripts/run_variant_annotation_pipeline.sh` into the staged directory
directly, the same way it rsyncs this directory in; `extended_ensembl_consequence.csv.gz`
isn't copied anywhere -- `annotate_simplified_consequence`'s Docker service
reads it straight from the repo bind mount -- see
`docs/variant_annotation_pipeline.md`.

## Not here on purpose

Large, static, non-CVFG-specific reference data (SpliceAI VCFs,
ClinVar/ClinGen/gnomAD caches, dbNSFP) stay wherever your variant-annotation
checkout already has them -- see `docs/variant_annotation_pipeline.md`.
They're read via variant-annotation's own repo bind mount and are unaffected
by the `VARIANT_DATA_DIR` override this project uses. The MANE summary is the
one exception to this: despite being generic, non-CVFG reference data, it's
small enough to commit to git, so it lives in this project's own
`data/input/reference/` and is staged automatically instead -- see above and
`docs/variant_annotation_pipeline.md`.

**Exception:** `AlphaMissense_hg38.tsv.gz` and `revel_hg38.tsv.gz` (plus
their `.tbi` indexes) are also excluded from *this* directory -- they're
large, generic, non-CVFG reference data, so they must be copied by hand into
`data/intermediate/variant_annotation/data/` before Step 13 runs, since
`step_13` reads them as `/work/data/...` paths. See
`docs/variant_annotation_pipeline.md` for why.

`data_frame_missense_variants_MP2_properties.csv.gz` (Step 13's MutPred2
scores export) *is* CVFG-specific, so it's committed to
`data/input/predictors/` instead and staged into
`data/intermediate/variant_annotation/data/` automatically by
`scripts/run_variant_annotation_pipeline.sh` -- gated on whether Step 13 is
actually about to run, since at ~350MB it's too big to copy on every
single-step invocation. See `docs/variant_annotation_pipeline.md` for
details.
